# CtxRun 后端 Crates 全面审查设计

## 概述

对 CtxRun 项目的 16 个 Rust crate 及主应用入口进行逐模块深度审查，涵盖代码质量、安全性、架构设计、性能和可维护性五个维度。审查结果仅输出报告，不做即时修复。

## 审查范围

**重点**：后端 Rust crates（16 个）+ 主应用入口 `src-tauri/src/`

**轻量覆盖**：前端架构（仅涉及前后端交互边界问题）

## 审查维度

每个 crate 按以下 5 个维度评估：

### 1. 代码质量
- 命名规范与一致性
- 错误处理模式（Result<T,E> 使用、错误传播链）
- 代码复杂度（函数长度、嵌套深度）
- unwrap() / expect() 滥用
- 死代码与未使用依赖

### 2. 安全性
- 命令注入风险（exec-runtime, browser-utils）
- SQL 注入（db crate）
- 路径遍历（文件操作）
- 不安全的 unsafe 块使用
- 敏感数据处理（transfer 中的文件传输）

### 3. 架构设计
- 单一职责边界
- 公共 API 表面积
- 与其他 crate 的依赖关系合理性
- 抽象层次是否恰当

### 4. 性能
- 异步使用模式（阻塞操作混入 async）
- 内存分配热点（clone 滥用、大字符串拷贝）
- 锁竞争（Mutex vs RwLock 选择）

### 5. 可维护性
- 测试覆盖
- 文档注释
- 配置硬编码

## 报告结构

### 每个 Crate 独立章节

```
## Crate: <name>

### 概述
- 职责描述
- 关键公共 API 列表
- 依赖的其他 crate

### 发现的问题
按严重度分级：

🔴 严重 — 可导致安全漏洞、数据丢失、崩溃
🟠 高 — 影响可靠性或可维护性的重要问题
🟡 中 — 应在后续版本修复的设计问题
🔵 低 — 代码风格、命名等建议性改进

每个问题包含：
- 问题描述
- 代码位置（文件:行号）
- 建议修复方向

### 亮点
- 值得保留的设计模式和良好实践
```

### 最终汇总

```
## 汇总

### 问题统计
- 按严重度统计
- 按类别（安全/质量/架构/性能/可维护性）统计

### 跨模块系统性问题
- 影响多个 crate 的共性问题

### 优先修复建议
- 按风险和影响排序的 Top 10 修复项
```

## 严重度评级标准

| 严重度 | 定义 | 示例 |
|--------|------|------|
| 🔴 严重 | 可被外部利用或导致数据丢失 | 命令注入、SQL 注入、未加密传输敏感数据 |
| 🟠 高 | 影响可靠性或安全性但需要特定条件触发 | unwrap 在生产路径中、竞态条件、资源泄露 |
| 🟡 中 | 设计不合理但不影响当前功能 | 过大的公共 API、不当的抽象、硬编码配置 |
| 🔵 低 | 代码风格和改进建议 | 命名不一致、缺少文档注释、冗余代码 |

## 执行方式

- 使用并行 Agent 同时审查多个 crate
- 每个 Agent 读取 crate 源码并按维度评估
- 主线程汇总结果并生成最终报告
